## User Flow and Decisions

An original reporting Tester can open an eligible report, choose Edit report, correct its description and save to the same report. Its discussion, state and assignment remain attached to that report. The editor accepts the four existing editable states in an active project. The database remains responsible for authorization and checks the current state when saving; a visible button does not grant permission.

If severity changed after the editor loaded, the first save retains every manual field and shows a focused warning above the form. A comparison also remains beside Severity. For example, the warning can show current High and selected Low. Another deliberate Save changes uses the newly observed revision and can save Low. A further intervening change warns again. Only trusted Developer attribution produces Developer wording.

Save changes and Cancel reuse the existing form and unsaved-navigation protection. AI generation and per-field application remain explicit actions and never save the report. Edit mode exposes no submission or draft controls. An uncertain save response retains the request identifier and exact payload for a safe retry. A changed payload or a deliberate conflict override receives a new identifier.

Mailbox provides All and Unread views, read status in words, changed-field names and current project context. Open report persists read status before navigation. A failed mark-read leaves the user in Mailbox with retry feedback. Delete removes the item through the mailbox repository; it does not call report deletion. Account-specific component keys and request guards prevent late responses from populating another account's screen.

Duplicate-linked reports must stay in their current project. P2011 uses the existing validation presentation: a general explanation and Project field error retain the manual input. Restoring the original project permits an otherwise eligible edit. No new controls were needed. Resolved and Closed reports remain read-only.

## Functions Created

- **ReportEditPage and Editor**, in [ReportEditPage.tsx](../../src/features/reports/ReportEditPage.tsx), receive the authenticated user and project/report repositories. ReportEditPage reads the route identifier and keys Editor by account, role and report. Editor loads the report and active projects, returns the prefilled form or an explicit loading, failed, missing or refused screen, and ignores completions after unmount. Its load retry repeats the reads. Developer access does not load the private editor. Tests include `reportEdit_developer_refusesWithoutLoadingPrivateEditor`, the eligibility families, `reportEdit_loadFailure_canRetryWithoutFalseMissingReport`, and `reportEdit_missingReport_showsMissingWithoutSave` in [report-edit-ui.test.ts](../../src/test/report-edit-ui.test.ts).
- **Editor.save**, in the same file, receives validated report input and returns an asynchronous completion. It locks overlapping saves, selects a new or reusable request identifier and calls only `editReport`. Saved and unchanged results navigate to the same report. A structured conflict updates only the observed severity revision and notice. Other domain errors retain fields and show feedback. Unavailable responses retain uncertainty and the retry request. `reportEdit_severityABAAndRepeatedChange_retainsInputAndRequiresEachExplicitRetry`, `reportEdit_uncertainFailure_reusesReceiptForSamePayloadAndPreventsOverlap`, the `reportEdit_%sFailure_retainsManualInput` family and `reportEdit_unmountedPendingSave_ignoresLateNavigation` cover these outcomes in [report-edit-ui.test.ts](../../src/test/report-edit-ui.test.ts).
- **MailboxPage and Mailbox**, in [MailboxPage.tsx](../../src/features/mailbox/MailboxPage.tsx), receive a mailbox repository and authenticated user. MailboxPage creates a fresh account-specific component. Mailbox lists the selected filter and renders cards, loading, empty or failed states. Its request generation guard ignores superseded reads. Listing itself has no write side effects. `mailbox_readyCard_displaysActorCurrentProjectChangedFieldsAndLiteralTitle`, `mailbox_successfulEmptyResult_distinguishesAllAndUnread`, `mailbox_failedLoad_showsRetryWithoutFalseEmptySuccess` and `mailbox_accountSwitchPendingLoad_ignoresOldPrivateItems` cover these behaviors in [mailbox-ui.test.ts](../../src/test/mailbox-ui.test.ts).
- **Mailbox.act**, in the same file, receives an item and a read, open or delete action. It prevents concurrent local mutations, calls the appropriate repository method and updates the visible items only after success. Open awaits mark-read before navigating. Read removes the card from Unread; deletion removes only its card. Failed actions retain context and show retry or uncertainty feedback. Tests are `mailbox_markReadInUnread_removesItemWithoutNavigation`, `mailbox_openPending_marksReadBeforeNavigationAndPreventsDuplicateRequests`, `mailbox_openReadFailure_staysWithItemAndRetryFeedback`, `mailbox_deleteItem_removesOnlyItemWithoutOpeningReport` and `mailbox_uncertainDelete_preservesItemAndAllowsSafeRetry` in [mailbox-ui.test.ts](../../src/test/mailbox-ui.test.ts).
- **Mailbox.reload**, in the same file, takes no arguments, clears stale feedback and starts another list attempt. It changes only screen state. The failed-load retry test above covers recovery.
- **HistoryChanges.valueLabel**, in [ReportDetailsPage.tsx](../../src/features/reports/ReportDetailsPage.tsx), formats one before/after value for an edited field. It uses trusted optional project names, the current project name when applicable, severity labels and a Not provided fallback. It returns display text without writes. The activity rendering coverage is recorded in the [final coverage details](final-coverage-detail.json), with actual activity shown in the [visual review](visual-review.md).

It does not authorize database writes. Existing discussion and workflow controls remain present. The editor eligibility tests and [report-ui.test.ts](../../src/test/report-ui.test.ts) cover the surrounding flow.
- **ActivityHistory and HistoryChanges**, in the same file, now accept `report_edited` entries from the extended history union and return an actor/time description plus only the changed input fields, showing both values. - **ProjectsApp**, in [ProjectsApp.tsx](../../src/features/projects/ProjectsApp.tsx), accepts the optional mailbox repository and returns the editor and mailbox routes alongside existing routes. Page keys continue to isolate route/account state. A missing injected mailbox repository returns an unavailable message. Route and navigation regressions are covered by [project-ui.test.ts](../../src/test/project-ui.test.ts) and [application-layout.test.ts](../../src/test/application-layout.test.ts).
- **AuthenticatedContent and withSession**, in [AuthenticatedApp.tsx](../../src/features/auth/AuthenticatedApp.tsx), now wrap edit, mailbox list, mark-read and delete calls. Each wrapper passes through its repository's inputs and result. An unauthenticated MailboxError triggers the existing account refresh behavior and is rethrown for screen handling. - **AuthenticatedRouter, createRouterStore and RoutedWorkspace**, in the same file, now carry the mailbox repository through the existing router lifecycle to ProjectsApp. They retain router disposal and account-key behavior. Their observable purpose is to provide the authenticated routes with the session-aware repository. Broader routing/session coverage is included in the [final coverage report](final-coverage-summary.json); private stale-response behavior is separately covered by the mailbox UI test above.
- **WorkspaceShell**, in [WorkspaceShell.tsx](../../src/shared/components/WorkspaceShell.tsx), returns a Mailbox link for either authenticated role and prevents Projects from appearing current on Mailbox. Its mobile menu and sign-out inputs remain unchanged. [application-layout.test.ts](../../src/test/application-layout.test.ts) verifies destinations and layout behavior.
